# retro（セッションの振り返り）

このセッションで起きた**手戻り**を洗い出し、どこを直せば次のセッションで起きないかを指摘する。主眼はユーザーの指示と仕事の進め方への指摘。ユーザーはそれを求めてこのスキルを呼んでいる。

**手戻り**とは、1往復以上を余計に使った箇所のこと。訂正、前提や制約の後出し、作り直し、方針転換、確認のための往復、Claude が聞かずに突っ走った結果のやり直しなどが当たる。

## 手順

### 1. 手戻りを洗い出す

会話を頭から追い、手戻りを全部拾う。それぞれに次の3つを付ける。

- **引用** — きっかけになったユーザーの発言（または Claude の発言）をそのまま
- **コスト** — 余計に使った往復の数と、その間に何が無駄になったか
- **言い換え** — 最初にどう言えば（どうしていれば）1往復で済んだか

指摘にするのは、引用で裏付けられる手戻りだけ。

完了条件: 会話の最初から最後まで追い終え、拾った手戻りすべてに引用・コスト・言い換えが付いている。

### 2. 直し先で振り分ける

1つの手戻りは、たいていユーザー側の曖昧さと Claude 側の確認不足の裏表になっている。誰のせいかは問わず、**どこを直せば再発しないか**で次の3つに振り分ける。

- **ユーザーの習慣** — 次回からユーザーが言い方や進め方を変えれば防げるもの。完了条件を最初に言わない、制約の後出し、判断を任せたのに材料が足りない、途中でのスコープ拡大など
- **環境** — CLAUDE.md・スキル・memory に書いておけば、ユーザーが毎回言わなくても防げるもの。このセッションでユーザーが口頭で補った方針や好みは、ここに入る候補
- **Claude の振る舞い** — Claude が聞くべきところで聞かなかった、確認せず断定した、指示を取り違えたなど

両側に原因があるときは、直すのが安い方に入れる。環境に書けば済むものは、ユーザーの習慣より環境を優先する。

環境に振り分けたものは、追記先のファイルと差分案まで作る。追記先は実際にファイルを読んで、既存の記述と重複しないことを確かめる。

完了条件: すべての手戻りがどれか1つの分類に入り、環境に入れたものには差分案が付いている。

### 3. 報告する

3つの分類ごとに、コストが大きい順に並べて出す。手戻りが無かった分類は「なし」と書く。セッション全体で手戻りが無ければ、そう報告して終える。指摘の数は、拾えた手戻りの数そのままにする。

環境の差分案は提示までに留める。適用はユーザーの了承を得てから行う。
