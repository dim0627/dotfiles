# refine-action（施策の反復精錬）

打ち手の案を出し、**まっさらな批判者**に潰させ、応えて書き直す。これを**新しい致命の指摘が枯れるまで**繰り返す。

対象は施策 — 何を実装するか、どこに手を入れるか、そもそも打つべきか。コードそのものではなく、コードに触る前の判断を扱う。

## なぜ回すのか

1周では終わらない。最初の案は、たいてい**直前に見た症状の形をしている**。目の前のログや報告に引きずられて、そこだけを塞ぐ**対症療法**に収まる。批判を受けて書き直すと次の案は一段深いところを触るが、今度は「その深いところに手を入れた副作用」を持つ。それも次の周の批判者が拾う。

案を書いた側は、なぜそう書いたかの理由を持ち続けるので、自分の思い込みには気づけない。**まっさらな批判者がそれを拾う。** これがループの本体で、周を重ねること自体が目的ではない。

## このループが壊れる3つの形

自己批判は放っておくと形だけになる。先にどう壊れるかを押さえる。

1. **丸くなる。** 批判に全部応えると、案から尖ったところが順に削られ、最後は誰にも反対されない無難な案が残る。無難な案はたいてい効かない。
2. **必ず何かを実装する方向に転ぶ。** 「批判されたら改善する」という形をしている以上、構造として「やめる」「今は計測だけする」に着地できない。
3. **批判が感想になる。** 「もっと慎重に」「リスクがある」は案を1文字も変えない。

## 入口ゲート

**現状が事実として押さえられてから**回す。このスキルは診断しない。何が起きているか・いつからか・どのくらいの頻度かが言えない状態で回すと、批判も改訂も想像の上で進み、周を重ねるほど想像が事実に見えてくる。

事実が足りなければ、**回す前に取りに行く**（ログ、DB、イベント、issue 履歴）。取れないものは「取れていない」と書き、以後それを前提にした指摘は**賭け**として扱う。

## 手順

### 1. 解く問題と評価軸を固定する

- **解く問題**を1文で書く。症状ではなく、解きたいことを書く
- **評価軸を2〜4個**決める。何を最適化し、何を犠牲にしてよいか。手間・可逆性・期限といった制約も軸に含める
- ユーザーに提示して**黙認を取る。止まるのはここだけ。** 軸が違っていると全周が無駄になるので、安い確認で高い手戻りを防ぐ

以後、軸は動かさない。周の途中で軸が増えると、前の周の却下判断が全部やり直しになる。

**完了条件**: 問題文と軸が書き出されていて、ユーザーがそれを見ている。

### 2. 初回の案を撒く

- **構造的に違う筋で3案**出す。違いは「どのレイヤに手を入れるか」で作る
- **1つは「打たない」案にする。** 放置した場合に実際に起きることを、頻度と母数で書く
- 各案を**実行できる粒度**まで下ろす。「Xを改善する」は批判できない。「Yを消してZにする」なら批判できる

手持ちの案を持ち込まれたときは、それを1案目に据えて残りを埋める。**持ち込まれた案にも「打たない」を並べる。** 案が既にあると、打つ前提が問われないまま周に入る。

**発散するのはここだけ。** 2周目以降は磨くフェーズで、新しい筋を足さない。足すと収束しない。

**完了条件**: 「打たない」を含む3案が、それぞれ実行できる粒度で書けている。

### 3. 周を回す

各周で次を行う。

1. **批判者を並列に立てる。** レンズ1つにつきサブエージェント1つ、**1メッセージにまとめて**投げる。渡すのは**現状の事実・案・評価軸・台帳**と、そのレンズの担当範囲だけ
2. **返ってきた指摘を刈る**（次節）
3. **残った指摘に応えて案を書き直す**
4. **台帳を更新する。** この周で**捨てた狙い**を必ず書く

**なぜその案に至ったかの経緯は批判者に渡さない。** 渡した時点で書いた側と同じ盲点を引き継ぐ。盲検が崩れるとこのループの値打ちは丸ごと消える。

1周目は3案すべてに批判を当て、生き残ったものを次の周に持ち越す。2周目以降は、**前の周で書き換えた部分に効くレンズだけ**を撒く。後の周で出る当たりはそこに集中する。

**完了条件**: 撒いたレンズの結果が揃い、台帳が更新され、案が書き直されている。

### 4. 刈る

まず**捨てる**。順に当てて、1つでも該当したらそこで落とす。

1. **軸に載っていない** — 固定した評価軸のどれにも紐づかない指摘。正しくても、今回の判断を変えないなら出さない
2. **応える具体が書けない** — 案がどう変わるかを1行で書けないものは、指摘ではなく**感想**
3. **台帳で見送り済み** — 同じものが戻ってきただけ

残ったものを格付けする。

- **致命** — この案は成立しない。前提が偽、根に届いていない、副作用が受け入れられない
- **穴** — 案は生きるが、埋めないと打てない
- **曖昧** — 決めれば済むが、まだ決まっていない

例外が1つある。**応えると案の中核が消える指摘**は、改訂ではなく**案の棄却**として扱う。「この批判に応えたら、もうこの案である意味がない」なら、案を書き直すのではなく落として残りの案に移る。**丸くなるのは、ここを改訂として処理したときに起きる。**

**完了条件**: 全指摘が、捨てられたか格付けされたかのどちらかになっている。

### 5. 停止を判定する

次のどれかで止める。

- **その周の新規の致命が0件** — 台帳にある既知のものは新規に数えない
- **改訂が前の周と同じ型の変更しか生まない** — 軸の中で行き止まり
- **4周を終えた**

致命を0件にすることは目指さない。**枯れたかどうかだけを見る。** 4周で止めた場合はまだ枯れていない。そのことを報告に書く。

### 6. 返す

- **案** — 1本に収束したならそれを。軸のどれを取るかで結論が割れたなら、**割れたまま並置する。無理に1本にしない。** 割れているという事実そのものが判断材料になる
- **効いた批判と、それにどう応えたか** — 周を追える形で
- **見送った批判と、その理由**
- **棄却した案と、棄却の決め手**
- **残っている賭け** — 裏の取れていない前提。施策は必ず賭けを含む
- **止まった理由**（枯れた / 行き止まり / 上限）

## 批判レンズ

レンズを分けるのは、1人に全部見せると見落としが1人分の偏りに揃うから。

- **根と症状** — 目の前の症状を塞いでいるだけではないか。同じ原因から出る別の症状を数え上げ、この案がそのうちいくつを消すかを言う。1つしか消さないなら**対症療法**
- **前提** — この案が効くために真でなければならないことを列挙し、裏の取れているものと**賭け**に分ける。賭けが案の土台にあるなら致命
- **副作用** — 案が触る対象を共有している他の経路を洗い、その経路の挙動がどう変わるかを具体で言う。「影響があるかもしれない」では指摘にならない
- **コストと可逆性** — 実際にかかる手間、巻き戻せるか、巻き戻せないなら何が固定されるか
- **計器** — 効いた／効かなかったが後から分かるか。分からないなら、何を足せば分かるようになるか
- **打たない場合** — この案を打たずに放置したときに実際に起きることを、頻度と母数の実データで言う。打つ価値に見合わないなら、それを言う

各批判者に要求するもの。

- 指摘1件ごとに、**何が起きるか**を1文で
- **根拠** — 現状の事実のどれを引くか。数えられるものは数える
- **案がどう変わるか** — 書けないなら出さない

すでに判定済みとして渡された指摘は再提示させない。

## 台帳

周をまたいで持ち回る。これが無いと、見送った指摘が毎周戻ってきて、新規かどうかの判定ができなくなる。

各項目に:

- 指摘の要約（同じものだと分かる粒度で）
- レンズと格付け
- 判断（**反映** / **見送り** / **案の棄却**）と、その理由
- 何周目のものか

加えて、周ごとに1行、**この周の改訂で捨てた狙い**を書く。元の案が持っていた狙いのうち、批判に応える過程で消えたもの。**丸くなっているかどうかは、この行が積み上がったときにだけ見える。**

次の周の批判者にはこの台帳を渡す。**反映したものも渡す。** 理由なく元に戻す指摘が来るのを防ぐ。
