**今起きている（か直前に起きた）障害の初動調査。** 原因クラスの切り分けと根拠の提示まで。修正とポストモーテムは含まない。

## 原則

1. **観測は人間の選択を待たない。** 観測面は固定（変更 / ログ / リソース / エラートラッカー）なので、聞くまでもなく全部並列で投げる。ユーザーが選んでいる時間を観測時間に変えるのが初動速度の正体
2. **エージェントには棄却を試みさせる。** 「支持する証拠を探せ」ではなく「**棄却しろ。できなかった場合だけ支持と報告しろ**」。偽陽性（無関係な異常値を犯人に仕立てる）が最も高くつく
3. **返り値は契約で固定する。** 生の数字を持ち帰らせない。統合がメインに乗ると会話が止まる
4. **取れなかったものを推測で埋めない。** 0件やログの不在を「異常なし」と読むのがこのスキルの最悪の壊れ方

## 手順

### 0. 入力の読み取り（コードは読まない）

貼られたものから **症状 / 発生時刻とその性質（突然・じわじわ・周期的）/ 影響範囲 / 観測元** だけ抜く。ここでコードベースを読み始めると初動が数十秒遅れ、並列化の利得が消える。

抽出できないものは推測せず「不明」のまま保持する（特に発生時刻を埋めると後段のデプロイ相関が全部無意味になる）。画像は自分で直接読む — 要約させるとグラフの形状という一番効く情報が落ちる。

### 1. 観測（並列・ゲート前）

**1-a. 何が使えるかを実測する。** 決め打ちしない。monorepo ではルート直下にない。

```bash
find . -maxdepth 3 \( -name node_modules -o -name .git -o -name .next -o -name dist \) -prune -o \
  -type f \( -name 'wrangler.json*' -o -name 'wrangler.toml' -o -name 'vercel.json' -o -name 'fly.toml' \) -print 2>/dev/null
grep -rl --exclude-dir={node_modules,.git,.next,dist} -E '@sentry/|SENTRY_DSN|datadog|newrelic|@opentelemetry' . 2>/dev/null | head -10
```

**同時にプロジェクト側の蓄積を読む。** ダッシュボードの在り処・接続手順・「このアラートは実影響より大きく出る」といった指標の校正は、汎用のリファレンスには原理的に書けない。ここにしかない。

- コンテキストに載っている `MEMORY.md` の索引を見て、関連しそうな項目の**本文を読む**（索引は載るが本文は読みに行かないと出てこない）
- `CLAUDE.md` / `docs/` の運用・監視の記述

**優先するが鵜呑みにしない。** 記録時点の情報なので、リソース名・権限・エンドポイントの実在は現物で確認する。

検出はヒューリスティックで網羅ではない（SDKの表記揺れ、CI側だけの設定、リポジトリ外の監視は拾えない）。**ヒットしなかった基盤を「使っていない」と結論づけない。** 検出結果は手順2に1行で載せ、間違っていればユーザーに訂正してもらう。

**1-b. 観測を全部 fork で投げる。** `Agent` を `subagent_type: "fork"` で起動する（バックグラウンドで走るのでメインは待たない。コンテキストを継承するのでアラート内容の再提示は不要）。

| 観測 | 中身 |
|---|---|
| 変更 | 発生時刻前後のコミット・デプロイ・設定変更 |
| ログ | アプリ / インフラのログ。形状と、どのエラー型が出ているか |
| リソース | インスタンス・DBのメトリクス。上限との距離。**飽和していたら消費の内訳まで掘る** |
| エラートラッカー | Sentry 等。**1-a で検出できた場合のみ** |

発生時刻が不明なら「直近24h」で投げ、判明した時点で絞る。叩き方は `references/probes.md`（**必要な節だけ読む**）。全エージェントに以下を渡す。

```text
## 出力形式（この形式のみ。前置き不要）
形状: <いつ・どう変化したか。急峻 / 階段 / 周期 / じわじわ。判定できないなら「不明」>
内訳: <何が上位を占めているか。実数値つき>
平常時との差: <比較窓と、その差>
取れなかったもの: <試したが取れなかったもの。なければ「なし」>
```

### 2. 仮説の提示（唯一の会話ゲート）

返ってきた観測を見せ、**原因クラスの仮説を具体名つきで4本まで**立てて `AskUserQuestion`（`multiSelect: true`）で選ばせる。

- **仮説を出す前に手元の観測と突き合わせる。** 既に棄却できるものは提示せずに落とす。自分で取ったデータに否定される仮説を出すと、会話がそこに引きずられる
- 「デプロイ起因」ではなく「30分前の <コミット名>」。具体名があると人間が一目で棄却でき、選択が速くなる
- 各仮説に「これを流すと何が分かるか」を1行添える
- 未到着の観測は `取得中` と明示する。**推測で内容を埋めない**（無関係なコミットが犯人として会話に定着する）

**同じ問いで「リポジトリの外で直前に変わったもの」も聞く**（環境変数 / フィーチャーフラグ / 外部SaaSの設定 / DNS・証明書 / 依存先の計画メンテ / 心当たりなし）。リポジトリからは原理的に見えないのに情報価値が高く、質問を1問足すだけなので往復は増えない。

原因クラスの引き出しは `references/probes.md` の末尾。

### 3. 仮説の棄却（並列）

選ばれた仮説ごとに `Agent` を1つ。**全部1メッセージ内で呼ぶ**（分けると直列になり並列化の意味が消える）。

```text
あなたのタスクは仮説「<仮説>」を **棄却する** ことです。

## 状況
<症状 / 発生時刻 / 影響範囲 / 観測元>

## 既に分かっていること
<手順1の観測結果と、プロジェクト側の知見。要約せずそのまま貼る>

## 使える観測手段
<検出した基盤と、probes.md の該当節>

## 制約
- 棄却できなかった場合だけ「支持」と報告する。曖昧なら「判断不能」
- **読み取り専用。** 書き込み・設定変更・スケール操作・統計のリセットは一切しない
- 大きなクエリを1発で投げない。小さく刻む（タイムアウトすると全部失う）
- 認証情報はファイルに書かない、標準出力に出さない
- 取れなかったものを推測で埋めない。コードは修正しない

## 出力形式（この形式のみ。前置き不要）
判定: 支持 | 棄却 | 判断不能
根拠: <観測した実データ。数値・時刻・ログの実文字列を必ず含める>
取れなかったもの: <なければ「なし」>
次に見るべきもの: <支持なら次に取る観測。なければ「なし」>
```

### 4. 収束

- **支持1本** → 「次に見るべきもの」に沿って深掘りし、根拠を厚くする
- **支持が複数** → 因果の連鎖として構成する（デプロイ → 接続リーク → 枯渇）。**真因は最上流**。並列に並べず、支持されたノードを1つも落とさない。最有力だけ残すと下流だけ対処して再発する
- **全部棄却** → 切り口が外れている。手順2に戻り**別の軸で**立て直す（時間軸を広げる / 影響範囲の前提を疑う / そもそも障害かを疑う）。言い換えて再投入しない
- **判断不能が多い** → 原因ではなく**観測手段の欠落**を報告する。それ自体が改善提案になる

途中で外から情報が入ったら遠慮なく仮説を組み替えてよい（**外部の情報で自分の仮説が棄却されるのは正しく機能している状態**）。ただし他人が持ってきた数値も鵜呑みにしない — 帰属やベースラインの取り方が誤っていることがある。自分の観測で裏を取り、食い違ったら食い違いごと報告する。

**2周して収束しないなら結論を出さない。** 「ここまで分かった / ここが観測できていない」で返す。根拠の薄い犯人を確定させて対策を打ち、実際の原因が生き残るのが最悪。

### 5. 報告

切り分けまで。修正の実装やポストモーテムには進まない（求められたら別途）。

```text
## 状況
<症状 / 発生時刻 / 影響範囲>　※不明な項目は「不明」と明記
検出した観測基盤: <誤っていれば訂正してもらう>

## 最有力: <原因クラス>
根拠: <観測した実データ。数値・時刻・ログの実文字列>
確度: 高 / 中 / 低 ＋ そう言える理由

## 支持された因果連鎖（支持が2本以上なら必ず）
<上流> → <中流> → <観測された症状>
各ノードに根拠となる実データ。真因は最上流 — 下流だけ対処しても再発する

## 棄却したもの
<仮説> — <棄却の根拠>

## 観測できなかったもの
<取れなかった観測と、その理由>

## 次に取るべき手
<最も情報利得の大きい観測 or 応急処置>
```

**棄却したものを必ず載せる。** 「何を見なくてよくなったか」は障害対応中に最も価値が高く、これがないと同じ場所を何度も調べることになる。

確度「高」は**時刻の一致や実ログの一致など、観測データによる直接の裏付けがある場合だけ**。消去法は「中」以下。
