# long-run（複数 PR のタスクを走らせきる）

1つのタスクを複数の PR に分けて、計画から PR の作成まで走らせる。ユーザーは途中で席を外している前提で動く。

このスキルで防ぎたい失敗は次の2つ。

- **途中の質問で止まり、止まったことに誰も気づかない。** 決めることは走らせる前に出しきる。走らせている途中で出た決めごとは推奨案で仮決めして進め、人間は走らせ終わってからまとめて決める
- **毎回、進め方をユーザーが説明し直す。** 進め方はこのスキルに書いてあるので、ユーザーから受け取るのはタスクの中身だけにする

## 0. 状態を外に置く

長く走ると本体の context が要約されて、細部が落ちる。進み具合は次の2か所に書き、要約のあとや次のセッションでは、まずここを読んでから再開する。

- **plan のファイル**: 何を作るか、PR の分け方、決めたこと
- **shu のタスク**: 今どの PR がどこまで進んだか（`note`）、仮決めしたこと（`log`）、PR の URL（`refs`）

再開するときは、このタスクの shu を読み、手順の続きから進める。

## 1. 計画を立てる

plan が無ければ書く。`write-plan` スキルがあれば使う。既にある plan・spec・チケットはそのまま入力にする。

plan には、技術設計に加えて **PR の分け方** を置く。PR ごとに次を書く。

- 範囲: この PR で入れること・入れないこと
- 依存: どの PR がマージされていないと作れないか。無ければ「なし」
- 確かめ方: この PR 単体で、何が確かめられたら完成か

依存の無い PR を増やす方へ切る。依存があると PR を積むことになり、マージの順番に縛られる。

**完了条件**: plan のファイルがあり、PR ごとに範囲・依存・確かめ方が書いてある。

## 2. 走らせる前に決めることを出しきる

ここが走らせる前に人間と話す最後の場面になる。後で止まらずに済むように、聞くことは全部ここで聞く。

集める問い。

- plan が決めていない外から見える決定。`review-plan` スキルがあれば流して、そこで出た問いを使う
- PR の分け方と順番、積むかどうか
- タスク名: PR タイトルのプレフィックス（`[Global-Stream] ...`）とスタック図の見出しに使う。PR 一覧や通知では、同じタスクの PR だと分かるのはタイトルだけなので、既定では付ける。リポジトリに PR タイトルの規約（Conventional Commits など）があれば、プレフィックスは付けずに図の見出しだけに使う
- 走らせ方の範囲: push してよいか、PR は draft で作るか、どこまで進めたら止めるか（全部の PR か、最初の N 本か）
- 仮決めで進めずに止まってほしい領域があるか。既定は無し

問いは1回にまとめて出す。それぞれに推奨案と理由を付け、ユーザーが「推奨どおり」と答えるだけで済む形にする。答えは plan と shu の `log` に書く。

許可の確認も黙って止まる原因になる。走らせる途中で使うコマンド（push、`gh pr create`、テスト）を並べ、許可が要りそうなものは今のうちに許可してもらう。

**完了条件**: 問いに全部答えが付き、plan と shu に書いてある。ユーザーが走らせてよいと言っている。

## 3. PR ごとに回す

plan の順番に、PR を1本ずつ次のように回す。

1. **ブランチを切る。** 依存が無ければ main から切る。マージされていない PR に依存するときだけ、その PR のブランチから切る（手順5）
2. **実装をサブエージェントに任せる。** 渡すもの:
   - plan のパスと、この PR の範囲・確かめ方
   - 想定外の決めごとが出たときの線引き（手順4）。外から見える決定に当たったら、推奨案と理由を付けて返させる。本体が仮決めして続けさせる
   - 返してほしいもの: 変えたこと、確かめたこと（実際に流したコマンドと結果）、自分で決めたこと
3. **本体でレビューする。** `review-code` と `security-review` を並列に流す。`security-review` は fork（Agent の `subagent_type: "fork"`）に任せ、`review-code` は本体で流す。`review-code` は中でサブエージェントを立てるので、fork にも実装役にも載せない。`security-review` は、差分が認証・認可、外部入力、外部 I/O、secrets、依存追加に触れる PR だけで流す。直すべき指摘は、実装役のサブエージェントに戻して直させる（`SendMessage` で同じエージェントに続けて頼む）
4. **PR を作る。** `create-pr` スキルを使う。タイトルの先頭に手順2で決めたプレフィックスを付ける。PR 本文の冒頭にスタック図を置き（末尾の「スタック図」）、本文に自分で決めたことと仮決めしたことを書く。作ったら、このタスクの作成済みの PR すべてのスタック図を更新する。レビューは作る前に済ませてあるので、作った後に流し直さない
5. **ブリーフを作る。** `brief-pr` スキルを PR に流す。走らせ終わってから、ユーザーが PR の中身を理解するための資料になる。本体の context を使わないように fork に任せ、待たずに次の PR に進む
6. **記録する。** shu の `note` を次の PR に進め、PR を `refs` に、ブリーフのリンクを `artifact` に足す

前の PR のレビューを本体で回しているあいだに、依存しない次の PR の実装を、別の worktree（Agent の `isolation: "worktree"`）で先に始めてもよい。

**完了条件（PR ごと）**: PR があり、レビューの直すべき指摘が残っておらず、ブリーフを頼んであり、shu に記録してある。

## 4. 途中で出た決めごとを扱う

実装やレビューの途中で、plan が決めていないことに当たる。分け方:

- **自分で決めてよい**: PR の中に閉じていて、後から直せるもの（関数の分け方、内部の命名、テストの組み方）。決めて、PR 本文の「決めたこと」に書く
- **仮決めする**: 外から見える振る舞い・データ・API の形が変わるもの、plan や手順2の答えと食い違うもの、他の PR の範囲を動かすもの。人間が決めることだが、走らせている間は聞かずに推奨案で進める

走らせている間は PR がマージされないので、仮決めが外れても直すのは PR の中だけで済む。代わりに、後から覆したときにどこまで直すかを追えるようにしておく。

1. 仮決めを shu の `log` に書く。決めたこと、選ばなかった案、理由、影響する PR
2. 影響する PR の本文の「仮決め」に同じものを書く
3. 手順2で止まってほしいと言われた領域に当たったときだけ、仮決めせずに止まる。止まる前に、その決めごとに関係しない PR を進めきる

## 5. PR を積む

マージされていない PR に依存するときだけ積む。

- 上の PR の base を下の PR のブランチにする
- 下の PR にレビューで修正が入ったら、上のブランチを載せ直す（`git rebase --onto <下の新しい先端> <下の元の先端> <上のブランチ>`）。push は `--force-with-lease` で行う
- **下を `gh pr merge --delete-branch` でマージすると、上の PR が閉じて開き直せなくなる。** 下をマージする前に、上の base を `gh pr edit <上> --base main` で付け替える。マージはユーザーがすることが多いので、上の PR 本文にもこの手順を書いておく

## 6. 走らせ終わったら報告する

止まったときも、全部終わったときも、同じ形で返す。ここが、人間が仮決めを決め直す場面になる。

- PR の一覧: リンク、一言の内容、ブリーフのリンク、状態（レビュー待ち、積んでいる先）
- 仮決めの一覧: 選んだ案、選ばなかった案、理由、覆したときに直す PR。ユーザーが「このまま」か「別の案」かを答えるだけで済む形にする
- plan から外れたこと: 何を、なぜ。plan のファイルにも反映する
- 確かめられていないこと: 手元で流せなかったテスト、CI に任せたもの

shu の `note` を報告と同じ状態にしておく。報告したら `PushNotification` で知らせる。1行で、PR の本数と、決め直してほしい仮決めの数を書く（例: 「long-run 完了: PR 4本、仮決め 2件の確認待ち」）

ユーザーが仮決めを覆したら、影響する PR を直し、積んだ PR は手順5のとおり載せ直す。直した PR のブリーフは作り直す。

## スタック図

このタスクの PR すべてに、本文の冒頭へ同じ図を置く。どの PR から開いても、全体の形と今いる場所が分かるようにするため。

````markdown
**Stack**（<タスク名>）

```
main
├─ #5764 language column on `persona.stream` (schema)
│   └─ #5769 store the streamer's device language
│       └─ #5773 open the stream home outside JP (carries #5767's commits until it merges)
├─ #5767 `checkUserRegion` takes `allowedRegions`   👈 this PR
└─ (not yet) follow and watch across the JP split
```
````

- 木の親子は base ブランチの関係にする。main から切った PR は main の直下に並べる
- 各行は PR 番号と一言の内容。その PR の本文では、自分の行の末尾に `👈 this PR` を付ける
- base 以外の PR のコミットを含むときは、`(carries #N's commits until it merges)` のように書く
- plan にあってまだ作っていない PR も `(not yet)` で載せる。全体の残りが見えるようにするため

図は1か所で組み立て、PR ごとに `👈 this PR` の位置だけ変えて、本文の図の部分を差し替える。PR を作ったとき、積み替えたとき、マージされたときに、作成済みの PR すべてを更新する。
