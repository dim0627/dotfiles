# 深掘り（`--deep` 指定時）

対象クラスタの代表 issue を `get_sentry_resource` で開き、以下を実施する。

1. スタックトレースを見る
2. **ミニファイされている場合**（`index.js:100:36977` のようにファイル名が潰れている）はソースマップが未アップロード。行番号は使えないので、**`culprit` / `transaction`（`POST /events` 等）とエラーメッセージ内の具体的な文字列（SQL のテーブル名・列名など）を手掛かりに `Grep` でコードを探す**
3. 該当コードを `Read` し、再現条件・影響範囲・修正方針を書く
4. 自力で原因が特定できない場合に限り `analyze_issue_with_seer` を使う（数分かかる）

ソースマップ未アップロードに気づいた場合は、それ自体を改善提案として報告に含める（以後のトリアージ精度が上がる）。

**完了条件**: 対象クラスタそれぞれに「再現条件 / 影響範囲 / 修正方針」の3点が揃っていること。埋まらなかったものは「特定できず」と明示する。
